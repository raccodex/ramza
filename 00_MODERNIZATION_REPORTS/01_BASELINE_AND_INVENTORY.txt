11. REQUEST FLOW MAP
--------------------
Normal frontend request:
  web server rewrite -> index.php -> assets/init.php -> config/database/bootstrap
  includes -> link1/controller selection in sources/ -> Wo_LoadPage() resolves a
  PHTML layout from the selected public theme -> response.

Admin request:
  admincp.php -> assets/init.php -> Wo_IsAdmin()/Wo_IsModerator() and maintenance
  checks -> sanitisation currently applied to request arrays ->
  admin-panel/autoload.php -> page query parameter is secured and checked against
  an explicit allow-list -> Wo_LoadAdminPage(<slug>/content) -> global admin shell.
  Moderator permissions are loaded from the user's permission JSON and enforced
  during page resolution. Admin in-page navigation uses admin_load.php and
  data-ajax URLs; actions commonly post to requests.php?f=admin_setting&s=<action>.

AJAX request:
  browser -> requests.php?f=<file>&s=<subaction> -> assets/init.php -> request
  validation/sanitisation -> include xhr/<file>.php -> endpoint emits the existing
  JSON or HTML contract. Admin partial navigation is separately served by
  admin_load.php.

Installer request:
  install/index.php directly handles page selection and POST installation.
  Current flow is terms -> requirements -> installation -> finish. It directly
  connects with MySQLi, writes config.php and nodejs/config.json, imports an SQL
  file line by line, updates configuration and inserts the initial administrator.
  It currently has no CSRF token, session step state or installation lock.

API request:
  legacy: api.php -> assets/init.php -> validates requested type/user and emits JSON.
  v2: api-v2.php -> assets/init.php + api/v2/init.php -> validates type,
  server_key and access_token -> api/v2/functions.php + exception definitions ->
  api/v2/endpoints/<type>.php -> JSON response.

Cron request:
  cron-job.php -> assets/init.php -> database-backed scheduled maintenance queries
  and service helpers. The script is not safe to invoke against production merely
  for a baseline because it mutates data; only a cloned test database is suitable.

13. PHASE 0 RISKS REQUIRING FOLLOW-UP
-------------------------------------
  - Existing configuration plus no installer lock permits installer replay.
  - Installer interpolates untrusted values into generated PHP and JSON.
  - Installer globally suppresses errors and exposes raw MySQL connection errors.
  - Installer rejects strict SQL modes rather than importing compatibly.
  - Installer expects a missing SQL filename and uses a semicolon-at-line-end parser.
  - Installer drops core tables on a licence/installation failure path.
  - Initial administrator password is inserted as SHA-1.
  - Installer and runtime contain 0777 permission assumptions.
  - Admin shell loads Google fonts/material icons from external CDNs.
  - Admin request sanitisation assumes scalar values and must be tested with arrays
    under PHP 8 before it can be considered safe.
  - Database and integration credentials exist locally; reports must never copy them.
